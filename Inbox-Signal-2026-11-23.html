The five, if you only read five

ranked

Ranked picks for an engineering lead at a software consultancy: the pieces that change how you advise a client on agent-era review, evals and delivery risk.

1
The Pragmatic EngineerRead

Railway's breach went from a build-system foothold to customers' AI provider keys in three phases

Railway's postmortem times each phase: monorepo theft took 5 steps in 11 hours, cloud SSH access 4 steps in 10 hours, and AI provider keys 3 steps in 3 hours. Railway was alerted eight minutes after the attacker began phase two and revoked the credentials one minute after they were used. The author's lessons are no shared build machines, fine-grained secret access, and response measured in minutes.

2
TLDR DevRead

Agents met 78% of required criteria on average, but only 29% of runs met all of them

Stripe's integration evals found agents met 78.1% of required criteria on average, and only 29.4% of runs met every required criterion. All 14 agent setups scored higher with Stripe's plugin. Spotify's worked example says offline evals explain only about 24% of online variance, against 60% modelled, so borderline changes still need A/B tests.

3
TLDR DevOpsRead

OpenJDK has a 9.2-severity pre-auth RCE in AVX-512 Base64 decoding: patch or disable the intrinsics

CVE-2026-114938 affects OpenJDK 17.0.6 and later on x86-64 and can enable pre-auth remote code execution in apps such as Jenkins, Confluence and Tomcat. The advice is to upgrade or disable Base64 intrinsics. The same issue reports Together AI's agent-written compiler beating its hand-written GPU megakernels by about 28% on B200 (2,118 vs 1,649 tokens/sec).

4
The Pragmatic EngineerRead

Human review of agent-written PRs is dying, so review releases instead

CodeRabbit's CEO Harjot Gill says he pushed more than 5,000 PRs in a month with agents, and estimates AI spend of about $250K to $275K a month, roughly $150 per PR; that per-PR figure is his own estimate. CodeRabbit's engineering team is about 40 people. An in-house CI system built in a week came in 50% below a $13M-a-year quote. His argument is that review capacity does not scale with agent output, so teams should gate on release risk.

5
Dev InterruptedRead

AI-written code still needs owners, and review capacity is the bottleneck because it does not scale

Freshworks CTO Murali Swaminathan says AI output often duplicates code, sometimes 100 lines where 10 would do. One customer deflected at least 30% of tickets after rolling out Freshworks AI agents. Adam Tornhill argues five parallel agents amount to about 50 tasks' worth of work, citing Robert Glass's requirements-explosion rule.

In a conversation, Satya Nadella describes 'software factories', with Azure's networking team using agents to run operations across more than 500 fibre network operators. RefactoringPromoRead

Most coordination exists because people left alone make too many wrong calls

The author splits coordination into sync (a meeting), async (decide, then wait for approval) and none (decide, and revert if wrong), ordered by throughput. The right mode depends on how likely a wrong decision is and how costly it would be.

Failure modes, data-store choices and the numbers that justify them.

System Design NuggetsPaywallRead

Event-driven failures are silent, so consumers must be idempotent and the event design sets the coupling

The post contrasts Event Notification, where consumers call back for details and so stay coupled at runtime, with Event-Carried State Transfer, where the event carries the state and consumers survive a producer outage. It notes delivery is at-least-once in practice and ordering holds only within a partition or key.

System Design NuggetsPaywallRead

Start from the measured bottleneck, and pick the cheapest fix that clears it

The post introduces twenty decision trees and an escalation ladder: fix the query, cache, scale up, add replicas, partition, specialise, shard, redesign. Its premise is that skipping rungs is how teams shard a database that only needed an index. The preview is truncated mid-tree.

System Design NuggetsRead

Retries configured at three layers turned a 90-second database failover into sustained overload

The failover finished at 10:14, but the service was still down at 10:20, with payment request volume at four times baseline. One user tap produced 12 database attempts over six seconds. The fix is one retry owner, exponential backoff with jitter, and a retry budget near 10% of traffic.

TLDR DevOpsRead

Salesforce pairs vertical and horizontal autoscaling on EKS for over $5M in savings

VPA adjusts CPU and memory while HPA scales replicas on proxy connection count, so the two controllers respond to different signals. The same issue notes Kubernetes plans to remove the kube-proxy IPVS backend in 2026, and GitHub's October availability report traces an outage to runner assignment waiting on database calls.

System Design NuggetsRead

Concurrency is about program structure, parallelism is about simultaneous execution, and the workload decides

The guide argues adding threads to an I/O-bound server, or an event loop to a CPU-bound pipeline, can make things slower. It puts thread stacks at 1 to 8 MB, and each context switch at a few microseconds plus cache disruption.

System Design NuggetsPaywallRead

Classify application state before choosing Redis, Postgres or Kafka

The guide gives Postgres thousands to low tens of thousands of writes a second on a primary, Redis hundreds of thousands of operations a second per instance, and Kafka hundreds of thousands to millions of records a second. It proposes classing state as authoritative, derived, ephemeral or in-flight, and warns that authoritative data held only in Redis is lost in a failover.

System Design NuggetsPaywallRead

Most slow databases come from query patterns, missing indexes or pool settings, not database limits

Rank queries by total time, calls times average duration: a 5 ms query run 50,000 times a minute costs more than a 3-second report run once a day. Its N+1 example makes 101 queries for a page of 100 orders. The body is truncated at Problem 4.
